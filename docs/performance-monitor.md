# 性能监视器

按下 Ctrl + Alt + Shift，然后输入 `debug`。开发/未打包测试版本允许 10 秒，正式打包版本允许 4 秒。超时、输入错误或非字符键会取消本次序列；不会打开普通开发者工具。

首次激活即记录，独立窗口可暂停/继续记录、导出报告。再次激活只显示窗口，关闭窗口不会停止采集。日志默认位于开发仓库根目录或正式程序可执行文件所在目录的 `outlogs/<时间>/`。无保存对话框；顶部通知显示实际路径。默认目录不可写时，自动回退到应用用户数据目录的 outlogs，并通过顶部通知显示实际目录，不要求用户设置。

采集器是独立 Electron utility 进程。原生 Rust 音频线程通过有界非阻塞队列交给独立写盘线程，解码 Worker 通过带随机令牌的本机 HTTP 端点直接上报。主进程或页面停止响应时，采集器继续记录 OS 进程数据及心跳缺失。整个进程被操作系统挂起或机器断电无法继续记录，已写出的 JSONL 可用于定位停止点。

## 指标定义

- 硬件：SDA 进程树 CPU（100% 为一个逻辑核）、工作集、私有内存（Windows）、进程 I/O 读写速率。Windows 用 GetProcessIoCounters，Linux 用 `/proc`，macOS 用 `proc_pid_rusage`；Windows 进程 I/O 含文件/设备传输，不等于物理磁盘吞吐。POSIX 采样器需要可执行的 Python 3，缺失会明确记录 unavailable。
- 网络：Electron 主进程 TCP 接收/发送字节，含无线远程音频与控制；另外记录 Chromium HTTP 编码接收字节、请求体发送估计，以及原生远程 TCP 读写字节。Chromium 调试器不可用时明确记为 unavailable；不伪称包含所有系统网络包，回环链路可能在两端被计数。
- 3D：CPU 提交时长、帧间隔、draw calls/三角形数量；支持 EXT_disjoint_timer_query_webgl2 时记录 GPU 执行时长。计时器不支持或结果 disjoint 时不产生虚假 GPU 时间。CPU/GPU 时长不是显卡整体利用率。
- 解码：每秒产出的音频秒数、nextFrame 耗时、消息处理总耗时（含等待、解封装、重采样、响度分析等）。`unitsPerSecond` 为每秒产出音频秒数；活跃解码速度可用音频秒数除以解码墙钟秒数。解码暂停时为零产出，不代表故障。
- HRTF：每对象连续方向卷积、滤波器更新、传统对象卷积；每路声床总线、反射总线卷积。记录次数、最低、平均、峰值、累计时长；卷积处理量为音频帧数，滤波器更新处理量为双耳 tap 数。嵌套阶段时间会重叠，并行累计时长不可当作整体墙钟时长。
- 路由：源混音与元数据处理、PCM 进入源队列、主进程发送到原生 ACK、计划提前量。ACK 不是已出声。
- 房间：生成总时长、子进程运行时长、应用总时长（包含控制排队与原生 ACK）、原生命令处理。begin 事件可定位尚未完成的任务。
- 输出：每块总渲染时长、输出回调耗时、欠载帧数、PCM 接收到对应输出回调的时长估计；可关联时另记解码开始到双耳回调估计。时钟投影采用 48 kHz 渲染时间轴，不包含操作系统/驱动之后的实际 DAC、蓝牙或声学延迟。跨进程按系统时间关联，系统时钟调整或 seek 时无效值会丢弃。

每秒一个 JSONL 汇总，报告 JSON 含环境信息、最近快照与最近两分钟历史，并引用原始日志文件。按对象/声道 ID 保留明细，不导出音频内容、密钥或用户环境变量。采集自身开销会体现在进程树；队列或磁盘背压丢样必须查看 `dropped` / error 字段。原生日志单文件限制 64 MiB，超过后重用文件，独立采集器持续汇总到性能日志。

补充：日志按约 32 MiB 分卷，单次记录保留最近 8 卷（约 256 MiB），原生文件上限 64 MiB，轮转带 generation 标记。导出生成 `report-latest.json`，重复导出更新同一报告。历史快照不重复保存累计明细，累计最低/峰值仍在报告 snapshot 中。

`decode.queue_wait` 单独记录消息队列等待，`decode.packet_push` 记录编解码器 push 的执行时间；`decode.output_audio` 的每秒处理量单位为“音频秒/秒”。原生输出健康指标中 FIFO 帧数换算为 48 kHz 毫秒，其余锁/回调微秒换算为毫秒。报告中的时间是诊断测量，开启逐路精细计时本身有开销。

Windows 已进行本机计数与独立进程采集验证；macOS/Linux 采样代码尚未在对应系统实机验证。


## 用户界面与覆盖范围

主界面使用中文步骤名称和单位，并分为电脑资源、声音与画面概览、逐路明细。明细可选择最近一秒/整个记录期间，以及解码、双耳、房间、声音输送、输出、3D、网络分类。原始 stage 名仅保留在日志中供开发排查。

| 范围 | 已接入位置 | 测量边界 |
| --- | --- | --- |
| 所有共用解码 Worker 的格式 | 任务排队、处理、解码器 push/nextFrame、响度分析、重采样、产出音频秒数 | 使用 PCM/ADM 直接解码的格式没有压缩解码器 push 计数；不能用零产出直接判定卡顿 |
| 原生独立对象 | 实际方向卷积、布局对象卷积、方向滤波器更新、近场参考、逐路混音 | 每路双耳处理计时；没有经过的分支无记录，不虚构独立对象数据 |
| 声床与房间 | 各声床总线、反射总线、房间生成/应用及等待 | 异步任务有 begin 与完成事件；并行及嵌套时间不能相加 |
| 原生输出后端 | 公共渲染块、输送确认、队列、输出回调和欠载 | ASIO、DirectSound、WASAPI 走共用原生埋点；设备内部与真实声学延迟不在测量范围 |
| 3D | CPU 提交、帧间隔、GPU timer query | 页面线程停止后无法继续产生 GPU 查询；独立采集器记录最后一次心跳 |
| 无线网络 | TCP、Chromium HTTP、WebRTC candidate-pair 字节差值 | WebRTC 统计由独立 RTC 渲染进程发送；不是整个操作系统抓包 |

尚不能称为每个平台、每个格式和输出设备均经过实机验证。纯浏览器/WebAudio 回退路径、手机实际出声时间、音频驱动内部处理没有完整原生逐路计时。已完成的 Windows 验证不能等同于 macOS/Linux 验证。


峰值提示：采集进程保存本次记录的最高值。当前值达到或刷新该值时，界面对应数字变红；下一次采样回落后恢复。暂停和未测得数据不触发红色。红色表示本次峰值，不自动代表错误；解码产出变高可能是正常提前解码。报告的 `peaks` / `peakKeys` 保留最高值及达到峰值的采样点，关闭监视窗口不会清空它们。


峰值详情：数字旁的 `i` 打开中文弹窗，显示冻结保存的歌曲、歌手、当时播放位置、发生时刻、指标及数值。峰值记录按产生时刻关联播放上下文，不用查看弹窗时的当前歌曲；native/decoder 聚合保留最大单次耗时的时间戳。位置显示约 1 秒精度；页面停止更新超过 2 秒的上下文会标为不确定，没有上下文则明确未知。软件可能提前解码/渲染，弹窗指的是当时播放进度，而非被处理的音频样本位置。原生健康信息中的历史计数没有原始发生时间，不会虚构歌曲归属。

导出 JSON 的 `peakRecords` 保留各指标最近最高值详情，历史/JSONL 中的 `peakEvents` 保留各采样点的歌曲上下文。进度达到峰值后回落仍可点 i 查看；正在打开的弹窗不会随切歌变化。

## 无音频、跨系统模拟（schema 1）

“导入日志模拟”从 `report-latest.json` 读取负载结构，由**当前版本**的本机原生渲染器在独立进程中执行合成数据计算。入口在音频设备初始化之前分流；不打开输出设备、不读取歌曲、不保存或播放计算输出。

- 便携字段：平台、架构、逻辑 CPU、版本化校准核、48 kHz 内部采样率、布局、对象/声床数量、位置与 HRTF 长度。
- 原机/本机使用同一个独立整数与内存校准核。原机等效耗时 = 当前 DSP 实测耗时 × 原机校准耗时 / 本机校准耗时。此值是近似，尤其不能消除 SIMD、核数、缓存、温控及系统调度差异。
- 导出最近最多 600 个负载快照，超过时 `truncated=true`；保留采集丢失数量。模拟最多抽样 12 个快照，每个独立建立引擎、预热，再测量 112 块。它是**稳态计算负载对比**，不是完整时序回放。
- 合成 HRTF 保持记录的方向数和滤波器长度，但不包含用户测量系数。当前不恢复精确房间/硬件处理、快照之间的运动、驱动、GPU、码流解码和网络队列；结果逐项提示范围。
- macOS/arm64 日志可作为 Windows/x64 输入；旧日志没有负载或校准时拒绝给出原机等效结论。Windows 验证不代表 macOS 实机通过。
- 不复制音频，不通过压缩、Base64、内存转储等方式夹带音频。导入日志仅作为有大小限制的 JSON 数据，不能指定可执行文件或命令。

### 解码故障包与验证边界

解码 Worker 在监视开启时保存最近 96 个结构化边界事件，失败时送入独立采集器，报告保留最近 32 份。白名单仅包括调用顺序、时间、帧字节数、采样位置、采样率、声道/对象数量、seek 和 epoch；排除原始帧、PCM、任意错误文本、文件路径和解码器内存。`containsAudio=false`。早期日志为 `coverage=decoder-boundary-only`；新版的内部检查点与生成用例见下方接入说明，仍不能宣称已采集第三方 codec 的全部分支。

针对码流错误的可执行复现使用**逐解析器的结构约束**：字段类型与范围、消费位数、包边界、状态转换、失败检查点以及解码实现/构建版本；以公开格式语法构造人工输入，替换所有音频载荷。生成用例必须在旧代码上命中原失败检查点，并在新代码上验证预期行为。无法命中则保持 `not-yet-reproduced`，不得以随机数据跑完或模拟旧耗时当作修复证据。仅有边界事件不具备自动重建任意压缩码流故障的能力。

性能模拟、结构生成测试和原系统设备验证是不同证据。当前 UI 不会把前两者标为 CoreAudio/WASAPI/ASIO 或蓝牙验证通过。

### 解码检查点接入（2026-09-19）

已将诊断从 Worker 边界接入 TrueHD、E-AC-3、DTS、AC-4、ALAC 的 pipeline 错误分支，以及 MPEG-H/IAMF 的包头、输入容量/消费量和参考解码器返回状态。它们记录稳定的检查点 ID、输入长度/位位置/声明长度/返回码（可用时），不记录载荷。错误文本仅在本机计算 64 位比较标签，不导出文本；该标签不是安全校验或无碰撞证明。底层第三方解码库没有暴露的内部状态仍不作已覆盖声明。

`decoder-checkpoints-v1` 报告保留检查点和错误标签；失败事件包含当前 WASM 与共享解析器构建的 SHA-256。检查点 ID（包括 `failure_01` 等现有编号）是兼容性接口，后续只能新增，不得按代码位置重新编号。Worker 开始新节目会丢弃旧节目未消费的检查点。关闭监视时不记录。

监视器新增 **验证解码故障**：导入日志后在隔离子进程运行当前 WASM/共享包头解析器。人工数据在本机生成，不读取歌曲或音频载荷，不连接输出设备。限制输入日志大小、检查点数量、候选数据长度、总执行时间；测试结果自动写入 outlogs。

已验证的人工用例包括 AC-4 截断同步帧、MPEG-H MHAS 超长包、IAMF LEB128 未终止/溢出，以及自动格式识别无同步字。TrueHD/E-AC-3/DTS/ALAC 另有固定小型人工候选，用于搜索是否能命中采集的错误标签；不保证能复现任意深层解码错误。没有生成器的检查点显示“尚无对应合成用例”。

结果含四种状态：检查点+错误标签匹配、仅检查点匹配、未复现、尚无用例。**没有再报错不自动等于修复成功，标签匹配也不等于原歌曲完整缺陷已经复现。** 对应失败分支的修复还须核对预期行为。

第一次匹配后结果保存生成器版本和参数；再次导入该结果会锁定同一生成配方，执行新代码，不重新搜索替代输入。因此可以用同一份结果对比改动前后。配方只允许内置生成器及有界数字参数，不接受脚本、命令、音频字节或外部文件路径。Windows/macOS 都使用同一 WASM 和格式解析规则；本机测试仍不证明另一个系统的驱动行为。

构建：`node scripts/build-core.mjs` 同时生成 Web/Node WASM、共享解析器 CJS 和构建标识。桌面打包前将 Node WASM 复制到 `performance-core`，正式包不依赖开发机仓库路径。
