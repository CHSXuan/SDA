# 播放进度跳转

跳转复用同一个 SdaPlayer、解码 Worker 和输出连接。epoch 隔离旧读取、解码响应及原生提交；目标位置有足够 PCM 后才启动输出。暂停时跳转只预缓冲，不自动开始播放。

## 加速路径

| 输入 | 策略 |
| --- | --- |
| WAV / RF64 / BW64 / ADM | 复用已解析的 BWF 元数据，按 blockAlign 直接读取目标前 100 ms 的 PCM，保留 SRC 预热和对象历史 |
| MP4/M4A ALAC、AC-3、E-AC-3 | 根据访问单元时间戳跳过无须解码的数据，保留约 3 秒预热 |
| MP4/M4A MPEG-H（mha1、mhm1 / 360RA） | 滚动保留最近独立帧之后的数据，选目标前 3 秒之前的独立音频帧；mhm1 补回该起点的配置和场景描述包。控制包未知、配置变化、单个区间超过 16 MiB 时从已保存起点顺序解码，不再因累计读过 16 MiB 而从头解码 |
| DTS、TrueHD、AC-4、IAMF、原始 MPEG-H 等状态解码路径 | 保留解码器依赖，跳过目标之前多声道 PCM 的导出、复制、重采样和传输，保留对象元数据；尚不是容器索引式直接定位 |

压缩文件目前仍顺序读取/拆包。网络盘、大文件、长 GOP 或没有可验证随机访问点的码流仍可能等待；不能将以上优化称为全格式秒跳。

PCM 和对象时间戳恢复到歌曲绝对采样时钟。44.1→48 kHz 等重采样按有理相位对齐，防止跳转导致小数采样偏移。跳转恢复原有响度增益；跳转后只分析的局部音频不会覆盖整曲响度缓存。

## 验证

`node scripts/test-seek-worker.mjs [媒体路径 ...]` 运行实际解码 Worker，对比连续解码与跳转后的 100 ms 音频、对象映射和起点。默认使用 MPEG-H / IAMF 测试文件；`SDA_SEEK_TEST_SECONDS` 设置目标秒数。先预热，再分别运行两次，以减少 WASM/JIT 冷启动干扰。耗时仅为读取和解码，不包括原生输出预缓冲。

2026-09-16 本机测试：ALAC 立体声、E-AC-3 Atmos、22 对象 MPEG-H M4A、DTS:X MKV、12 对象原始 MHAS、IAMF，以及 22 声道 ADM 的目标音频均逐样本一致。另有 BWF 非零读取起点、SRC 相位与尾部、MPEG-H 配置变化回退、内存上限、暂停/增益保持和过期 epoch 测试。TrueHD 和 AC-4 共用的快速丢弃路径已接入，但本次没有可用的完整支持格式样本完成音频对比；所试 AC-4 IMS 文件由现有解码器报告不支持，不能算验证通过。
