# 无线远程：仅控制

仅在电脑端设备权限中选择“仅控制”。手机配对页与更多菜单不提供模式开关，连接时自动遵循主机权限，不使用浏览器保存的模式偏好。

仅控制使用经过原有 HTTPS、密钥/设备授权校验的 WebSocket。它占用一个设备连接名额，必须拥有控制权限，不创建 PCM/HLS/WebRTC 音频接收器，不加入音频同步或缓冲等待。播放、切歌和打开媒体按电脑端播放处理，不触发“手机播放时电脑静音”。进度、列表、封面及空间视图仍同步主机状态。

可与其他收听设备同时连接，受主机最大连接数限制。仅控制不是后台音频保活：手机系统仍可能挂起后台网页。权限撤销会断开连接。

验证：远程网页和静音相关的 18 项测试通过；新增测试确认仅控制不建立音频发送器，并验证与收听设备并存、收听设备断开后仍可控制。前端类型检查及生产构建通过。

电脑端设备权限与首次批准均支持“收听与控制 / 仅收听 / 仅控制”。仅控制权限由主机拒绝 PCM、WebRTC、HLS 和原生音频连接，网页根据授权结果自动进入控制模式；不能通过关闭手机端开关绕过。权限修改会断开原连接，重新连接后采用新权限。

仅控制模式首次点击网页播放后，会创建本地零采样 WAV 循环作为系统媒体控制载体，不接收歌曲音频。系统播放/暂停按钮控制主机。暂停时同步暂停本地载体，断开时停止并释放。已撤回“暂停后持续播放静音”的实验，避免实际媒体状态与系统暂停状态冲突。系统歌曲位置和总时长来自主机，不使用载体的循环时间。这会占用手机媒体会话；Safari 灵动岛显示和后台存活仍需 iPhone 实机验证。

系统控制激活由手机的播放/选曲操作直接触发，与主机播放命令在同一点击流程中发起；不要求先操作电脑或再点页面。主机旧状态在待确认播放/暂停期间不会反向覆盖本地媒体载体。

独立 AudioContext 保活实验：用户首次点击播放时建立单声道零 PCM 循环，暂停歌曲时仍运行，媒体元素仍真正暂停、系统歌曲位置仍取自主机。断开时释放。它会额外占用音频会话和电量，不强制抢回被来电或其他 App 中断的会话；iOS 是否把纯静音视为后台播放及是否保留灵动岛仍需实测。诊断增加 keepAlive、keepAliveTime、keepAliveError，避免把桌面测试误当成 iPhone 验证。

2026-09-17 实机反馈：用户确认 AudioContext 保活配合自动重连解决了连接问题。主机日志记录暂停切后台后 keepAlive 持续为 running，keepAliveTime 持续增加；灵动岛暂停后一段时间仍消失，此问题未解决，不能将连接恢复或桌面测试通过视为灵动岛已修复。
